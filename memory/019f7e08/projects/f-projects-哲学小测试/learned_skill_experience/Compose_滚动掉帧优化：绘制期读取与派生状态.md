## 输入
- Compose 列表/长文滚动场景出现掉帧
- 进度条或悬浮组件在组合阶段直接读取滚动状态（如 `scrollState.value`）

## 步骤
1. **定位问题**：检查是否在组合阶段（Composition）读取了会随滚动变化的状态，导致每帧触发重组/重布局。
2. **移除冗余嵌套**：删除不必要的 `BoxWithConstraints` 等子组合布局，减少 Subcompose 开销。
3. **分离读取时机**：
   - 对于视觉反馈（如进度线填充）：改用 `Modifier.drawBehind` 在**绘制阶段**直接读取滚动位置，仅触发小区域重绘，不进重组/布局流程。
   - 对于数值显示（如百分比文字）：使用 `derivedStateOf` 将浮点滚动值转换为整数百分比，仅在数值变化时重组。
4. **优化数据流**：避免在 `snapshotFlow` 中构造临时对象（如 `Pair`），尽量在收集端读取所需属性。

## 输出
- 滚动期间主线程不再发生重组和布局，仅进行手势分发、图层平移和小区域绘制。
- 编译构建成功，无新增警告。

## 注意事项
- 此方法适用于任何因“组合期副作用”导致的滚动卡顿场景。
- `drawBehind` 是解决纯视觉反馈（不依赖布局参数）的最佳实践。
- `derivedStateOf` 必须配合 `remember` 使用，且转换逻辑应轻量。
