## 输入
- 前端页面存在元数据（如人物、分类等）下拉选择框
- 需要确认是否完全依赖后端 API 动态加载，而非硬编码兜底

## 步骤
1. **全局搜索**：使用 Grep 查找所有硬编码数组定义（如 `let PERSONS = [[...]]`）及接口失败时的 fallback 逻辑。
2. **删除兜底**：移除所有硬编码默认值，将变量初始化为空数组（`[]`）。
3. **强化防御**：在接口调用后增加严格校验（检查是否为数组），若为空则抛出明确错误提示或阻止后续逻辑，避免隐式使用旧数据。
4. **全量排查**：确认树形结构、关联数据（书/章/参照文章）均无硬编码，全部来自 `/api/tree` 等动态接口。
5. **实测验证**：启动服务，通过浏览器控制台检查变量值（如 `PERSONS.length`）及 UI 选项数量，确保与数据库一致。

## 输出
前端无任何硬编码元数据，所有下拉选项完全由后端 API 驱动；接口失败时不再静默降级为硬编码，而是暴露问题。

## 注意事项
- **核心原则**：前端展示层严禁包含业务数据的“兜底值”，防止数据源变更（如新增人物）时界面不更新。
- **异常处理**：当接口返回空数据时，应视为严重错误（可能是数据库未初始化），需立即提示用户检查后端，而非假装正常。
- **验证重点**：不仅检查变量是否存在，还要检查其实际长度和内容是否与预期数据库记录匹配。
