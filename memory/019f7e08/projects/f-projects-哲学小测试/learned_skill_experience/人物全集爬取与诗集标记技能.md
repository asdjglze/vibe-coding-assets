## 输入
- 目标网站主页链接（如 https://www.marxists.org/chinese/index.html）
- 现有已收录人物清单（people.json）
- 已有抓取的结构数据（structure.json）

## 步骤
1. **扩充人物清单**：解析主页HTML提取所有人物子目录链接，排除非人物条目（如组织、图片馆、搜索页等），合并到现有清单。
2. **抓取主页结构**：对新增人物并发抓取主页HTML，解析出分段标题、书籍链接、CHM文件列表，保存为 structure.json（注意限流间隔≥1.5s，避免被封IP）。
3. **增量下载文章**：遍历 structure.json，对未下载过的人物调用 crawl_person 脚本，串行或低并发处理（max_workers=2），支持断点续传（检查 articles.json 和 state.json）。
4. **重建数据库目录**：运行 rebuild_catalog.py，自动识别诗集（书名匹配 `诗(集|选|抄|稿|存|录|草|篇|歌|词)` 正则），将对应文章的 kind 标记为 'poem'，同时更新 toc_entry 的 kind 字段。
5. **同步数据库**：确保校对工具（notes_editor）和打包资源（app/src/main/assets/databases/quote.db）双副本一致，重新计算 MD5。
6. **App端兼容**：修改 ArticleDao 查询，书内搜索需包含 kind='poem' 的文章；BookshelfRepository 中搜索结果按 kind 区分 ContentKind。

## 输出
- 148个人物的完整数据（articles.json + structure.json）
- quote.db 中 book.kind='article'（诗集书的book表仍用article，仅文章和toc标poem）
- App端搜索能命中诗词内容

## 注意事项
- **主页URL可能是 index.html 而非 index.htm**，需实际测试确认。
- **部分人物主页可能没有文章链接**（如铁托只有PDF），这是正常情况，不是解析bug。
- **爬虫限流**：并发数≤2，请求间隔≥1.5s，否则可能被服务器封禁。
- **诗集判定**：仅整本诗集才标记 kind='poem'，单篇诗歌在文集中不算。
- **book表的kind字段保持'article'**，App通过toc_entry的kind区分内容类型，避免键冲突。
- **增量抓取**：probe_structure.py 和 crawl_new.py 都支持跳过已有人物，只需重跑即可。
- **App编译需设置JAVA_HOME**：`$env:JAVA_HOME='C:\Program Files\Android\Android Studio\jbr'`
