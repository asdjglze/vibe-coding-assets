## 输入
- 批量导入的内容（如爬虫文章）未建立目录条目（book/toc_entry），导致校对工具主界面无法显示
- 前端存在硬编码的人物列表（如 [[1, "鲁迅"], [2, "毛泽东"], [3, "编者"]]），无法识别新作者

## 步骤
1. **定位根因**：确认校对工具主界面依赖 `/api/tree` 接口，该接口仅从 `book/toc_entry` 表组装树；硬编码列表限制了人物选择。
2. **后端改造 - 动态补充树节点**：在 `api_tree` 中查询未出现在 `toc_entry` 的文章，按 `source` 字段归组，动态生成 `bookId=None` 的虚拟书节点挂载到对应作者下，确保所有文章可见。
3. **后端改造 - 新增人物接口**：实现 `/api/persons` 接口，从 `person` 表读取全部作者（id, name），供前端动态填充。
4. **前端改造 - 动态加载人物**：移除硬编码 `PERSONS` 数组，改为启动时调用 `/api/persons` 获取列表，保留原硬编码作为兜底值。
5. **性能优化（可选）**：若统计耗时过长，合并注码正则表达式（一次扫描替代多次）、增加无候选字符行快速预筛、使用字典计数替代 O(n²) 重复检测、引入基于 (ref_id, md5) 的进程内缓存。

## 输出
- 校对工具主界面完整显示所有文章（含未建目录条目者），按 source 分组展示
- 新增文章弹窗的人物下拉框包含数据库中所有作者
- 控制台无报错，页面加载时间符合预期

## 注意事项
- 动态生成的虚拟书节点 `bookId` 为 `null`，需确保前端渲染逻辑兼容此情况
- 缓存策略需注意内存限制，建议设置最大条目数并定期清空重建
- 新旧算法对比验证是确保性能优化不破坏业务逻辑的关键步骤
