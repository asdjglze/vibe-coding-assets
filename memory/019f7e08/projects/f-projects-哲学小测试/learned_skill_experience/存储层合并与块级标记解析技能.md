## 输入
- 需要将独立实体（如诗词）合并到主实体表（如文章），并保留原有 UI 展示逻辑
- 需要新增块级标记语法（如 [诗]）实现特定排版效果
- 需要保证校对工具与 App 端数据一致性

## 步骤
1. **数据层改造**：
   - 主表增加分类列（kind）和扩展字段（dynasty）
   - 移除原独立实体类，改为投影类型（由 DAO 查询过滤生成）
   - 更新数据库版本（version++），确保 Room schema 导出新 JSON
2. **解析器扩展**：
   - 新增 MdBlock 子类型（如 Poetic），定义行首标记正则（^\[诗\](.*)$）
   - 实现惰性延续逻辑：遇空行/其他标记行/脚注定义行时结束当前块
   - 确保块内 spans 走标准行内解析（加粗/斜体/脚注等不互斥）
3. **渲染器实现**：
   - 新增居中渲染组件：按句读标点断行 → 逐行测量最长宽度 → 超宽整体缩放 → Column 居中布局
   - 旧数据兜底：未标记段落自动走相同渲染器（内容不丢）
4. **工具链适配**：
   - 校对工具：添加快捷按钮、CSS 样式、JS 块扫描与占位符替换逻辑
   - 数据库迁移脚本：ALTER TABLE 加列 → poem→article 逐行迁入（段首加标记）→ toc_entry 重映射 → DROP 旧表 → 更新 identity_hash
5. **打包验证**：
   - 全量重建数据库（gen_seed_db.py）→ 校验 schema 与行数 → 同步双副本 → 重算 MD5 → 编译 APK

## 输出
- 数据库：poem 表消失，article 表含 kind='poem' 记录，所有诗词正文带 [诗] 标记
- App：诗词阅读页走 md 渲染（居中逐句），首页卡片/桌面组件视觉零变化
- 校对工具：诗词条目预览居中，支持手动添加 [诗] 标记
- 构建产物：assets 库与 notes_editor 主库 MD5 一致，APK 编译通过

## 注意事项
- 迁移前必须备份主库（notes_editor/quote.db）
- 双副本同步后必须重算 MD5，防止下次打包覆盖丢失
- 块打断逻辑需双向维护（父块打断列表 + 子块打断列表）
- 旧数据兜底策略：未标记段落应能正常渲染（避免回滚风险）
