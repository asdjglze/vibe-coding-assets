## 输入
- 用户提出多条件组合的UI/UX变更需求（如切换阅读模式时的默认排版、弹窗交互、功能开关、视觉元素样式等）
- 需求包含具体逻辑约束（如弹窗三选一、特定功能在特定模式下禁用、颜色圆分排算法）

## 步骤
1. **需求拆解与定位**：将用户自然语言描述的多点需求拆解为独立的功能点（如预设值、弹窗逻辑、文案风格、功能开关、UI布局算法），并在代码库中搜索对应模块。
2. **验证现有实现**：使用Grep/Read工具逐一核对各功能点是否已存在代码实现，确认无遗漏或回退。
3. **逻辑一致性检查**：重点验证跨模块联动逻辑（如翻页模式触发时，是否同时关闭分享入口、保留收藏、应用预设排版）。
4. **算法与细节复核**：针对自定义算法（如颜色圆均匀分排），验证其边界条件和数学逻辑是否符合用户描述的规则（如行数计算、每行数量差值控制）。
5. **文案风格确认**：检查交互文案是否满足“文学性叙述”而非“列表式枯燥表达”的要求。

## 输出
- 确认所有需求点均已正确实现且编译通过
- 逐条对照用户原始需求汇报实现状态（含代码位置引用）

## 注意事项
- **交互逻辑闭环**：模式切换类需求需同步检查关联功能的开关状态（如翻页模式=墨水屏优化，需关闭分享但保留收藏）。
- **文案风格**：用户明确要求“文学性”文案时，避免使用标准列表格式，需用叙述性语言描述后果。
- **算法鲁棒性**：对于UI布局算法（如分排），需验证极端情况（如刚好整除、余数分布）是否符合“最后一行与上面行差值最小”的原则。
