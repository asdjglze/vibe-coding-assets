## 输入
- 用户提供的核心观点或理念（如："理念不代表正确，要通过错误理解时代"）
- 目标应用场景（如：App 中的说明文字、简介等）

## 步骤
1. **需求转化**：将用户的抽象理念转化为具体的应用文案，注意保留核心逻辑（如："了解错误 -> 理解时代 -> 对应当下"）。
2. **精简优化**：根据用户反馈（如"写太大段"），删除冗余铺垫，直接切入主题，确保文案紧凑。
3. **精准替换**：使用 `SearchReplace` 工具定位原文本进行替换，避免误删其他内容。
4. **构建验证**：修改完成后，立即执行编译命令（如 `gradlew compileDebugKotlin`）确认代码无语法错误且构建成功。

## 输出
- 文案已按用户理念更新且篇幅精简
- 项目编译构建成功（BUILD SUCCESSFUL）

## 注意事项
- 用户可能直接提供长句或抽象概念，需主动提炼核心逻辑而非照搬。
- 任何文本修改后，务必执行编译检查，防止因换行符或引号问题导致 Kotlin/Java 编译失败。
