## 输入
- 播放列表显示混乱（文字/封面/声音不一致）
- 播放器状态异常（如恢复播放失败报错）

## 步骤
1. **核对服务器端数据**：检查播放列表 JSON 文件及 API 返回，确认 title/coverUrl/streamUrl 是否匹配。
2. **验证 ID 与内容的一致性（关键）**：用 Airsonic getSong 按 ID 重新查询，对比返回的 title/artist 与缓存字段是否一致。注意：服务端日志中请求 URL 正确（如 /api/stream/37916）并不能证明内容正确——媒体库重建后 ID 会重新分配，同一 ID 可能指向完全不同的歌曲。必须用 getSong 实测 ID 当前指向什么。
3. **分析服务端日志**：查看 nohup 日志中的 jump/consume 记录与对应的 stream 请求，确认播放顺序（仅用于定位流程，不用于验证内容）。
4. **定位前端竞态条件**：排除 ID 错位后再检查前端多流程竞争（SSE 自动播放、用户点击、刷新重置）。
5. **实施修复**：
   - 播放列表缓存加载时抽查 ID 与当前 Airsonic 一致性，错位即作废缓存重新生成。
   - 音频流/封面响应加 Cache-Control: no-store 防浏览器缓存旧内容。
   - 统一自动播放触发点、刷新保持高亮、AbortError 静默处理。

## 输出
播放列表文字、封面与实际播放音频完全一致；无虚假报错。

## 注意事项
- 诊断时需区分"后端数据错位"、"Airsonic ID 错位"与"前端状态不同步"三种情况。
- Airsonic 媒体库重建后所有歌曲 ID 重新分配，播放列表缓存若不过期会导致"文字/封面/声音"三路全部不一致。
- 前端竞态通常表现为：用户操作被后台事件覆盖、UI 状态滞后于内部状态。
