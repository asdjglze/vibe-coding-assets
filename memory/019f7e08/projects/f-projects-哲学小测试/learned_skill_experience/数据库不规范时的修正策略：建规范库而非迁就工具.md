## 输入
- 场景：数据库存在不规范结构（如未建立 book/toc_entry 目录的文章）
- 约束条件：需保证数据规范性与工具逻辑的一致性

## 步骤
1. **识别问题**：发现工具通过“动态书”（bookId=None）等 hack 逻辑迁就不规范数据，导致结构混乱。
2. **决策反转**：放弃“让工具适应不规范数据”的思路，确立“先建规范数据库，再恢复工具原样”的原则。
3. **撤销 Hack**：移除工具中所有基于 source 动态归组文章的临时逻辑（如 `dyn_by_person`），恢复 `api_tree` 仅从标准 `book/toc_entry` 组装目录树。
4. **重建规范**：编写脚本遍历人物文章，按 `source` 字段为每位作者创建规范的 `book` 记录，并为每篇文章创建顶层 `toc_entry` 条目（level=0, parentId=NULL）。
5. **验证与同步**：检查动态书数量为 0，确保所有文章挂载在真实书籍下；同步双副本数据库并重算 MD5。

## 输出
数据库结构完全规范化（无孤儿文章，无动态书），工具接口返回标准目录树，加载性能正常。

## 注意事项
- **核心原则**：数据结构必须规范，工具逻辑应适配标准 Schema，而非反向妥协。
- **规范定义**：`book` 表需包含 `personId`, `kind`, `source`, `title`, `author`, `sortOrder`；`toc_entry` 需关联 `bookId` 和 `refId`。
- **避免陷阱**：不要为了短期便利引入临时 hack 逻辑，长期维护成本极高且易导致数据不一致。
