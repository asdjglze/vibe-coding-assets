## 输入
- 电子书 base URL（如 `https://.../files/mobile/`）
- 页码探测需求（需准确识别总页数）

## 步骤
1. **基础探测**：使用 GET 请求 + 魔数（图片头 `\xff\xd8` 或 PNG 头）判断单页是否为有效图片。
2. **处理坏页**：区分 HTTP 404（真缺页）与 HTTP 200 但内容为 HTML 的“坏页”（非图片内容）。
3. **二分粗定位**：在区间内二分查找最后的好页，但需注意坏页可能破坏单调性导致误判。
4. **延伸容错**：二分结果后，逐页向上扫描；仅当连续 12 个真 404 或累计 60 次非图结果时，才判定为书尾；中间出现的坏页（200-HTML）不计入边界证据。
5. **重试机制**：对非 404 状态码的请求进行多次重试（间隔递增），排除临时网络波动。

## 输出
- 成功返回 `(start_page, end_page)` 元组，其中 `end_page` 为最后一张真实图片页码。
- 若无法探测，返回 `(None, None)`。

## 注意事项
- **坏页漂移**：服务器端坏页集合可能随时间变化，不能依赖单次探测结果，必须采用“容忍延伸”策略。
- **URL 模板**：确认目标站点的页图 URL 模板（如 `/files/mobile/N.jpg` vs `/doc/I/N`），错误模板会导致全 404 假象。
- **扩展资源**：适用于存在“软失败”（HTTP 200 但内容无效）的 PDF/图片下载场景。
