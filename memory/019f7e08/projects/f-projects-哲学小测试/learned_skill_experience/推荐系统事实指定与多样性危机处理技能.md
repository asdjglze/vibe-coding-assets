## 输入
- AI 精选后的歌曲列表
- 用户具体请求（specific_requests）

## 步骤
1. **多样性危机检测**：统计歌单中歌手/流派分布，若主导占比≥80%且至少4首，且用户未明确指定该歌手/流派，则标记为"多样性危机"。
2. **触发补充流程**：检测到危机或数量不足时，进入三路召回补充（网易云交叉匹配 + 本地特征库检索 + Airsonic 扩展搜索）。补充是纯追加式：把排序池里已定的歌作为 previously_selected 告诉 AI（要求语义去重、不重复选），只从新召回候选中按缺口数筛选，结果仅追加进排序池并 id 去重。禁止 AI 对已定歌曲做插入/替换/移除决策。
3. **事实指定判定**：补充轮次用尽后若仍无法消除危机，判定为"事实指定"（用户需求本就如此），设置 `force_keep=True`。
4. **统一精排强制通过**：循环内严禁调用精排砍歌，循环结束后仅统一精排一次（`force_keep=True` 时跳过同歌手/专辑数量上限），之后不再回补。

## 输出
- 日志记录危机详情及事实指定判定结果
- 最终歌单包含所有符合需求的歌曲，不因单一来源被强制截断

## 注意事项
- 用户明确指定歌手/流派时，即使占比高也不判危机，直接走精排（此时上限规则本身已跳过）
- 补充流程需确保三路召回的候选均具备可播放 ID（如 Airsonic ID）
- 补充轮筛选复用 _select_songs 并传 min_count_override/max_count_override 按缺口控制选歌数量
