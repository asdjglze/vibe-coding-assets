## 输入
- 电子书图片链接（任意一页即可，需包含 `files/mobile/` 路径前缀）
- 起始页码、结束页码（结束页留空可触发自动探测）
- 书名、输出目录

## 步骤
1. **环境探测**：
   - 发送 HEAD 请求验证 URL 规律及是否支持 HEAD 方法
   - 尝试访问越界页（如 9999.jpg）确认返回 404 行为
   - 若支持 HEAD，则用于后续自动探测总页数；否则需手动指定范围
2. **下载阶段**：
   - 解析链接前缀与 query 参数，构建 `{页码}.jpg?{query}` 格式
   - 使用多线程（推荐 8 线程）并发下载，单页失败重试 3 次
   - 遇到 404 缺页跳过并记录日志，不中断任务
3. **合并阶段**：
   - 使用 PyMuPDF (fitz) 按顺序读取图片
   - 逐页创建 PDF 页面并原样嵌入 JPEG（保持原始分辨率）
   - 实时反馈合并进度（x/y）
4. **自动探测（可选）**：
   - 若结束页为空，从起始页开始连续 HEAD 探测
   - 连续 5 个 404 即判定为书尾，自动修正结束页码

## 输出
- 生成的 PDF 文件路径
- 成功下载的页数、失败的页数、缺页列表
- 合并后的 PDF 大小（通常仅比原图总和略大，结构开销极小）

## 注意事项
- **无损合并**：PyMuPDF 直接嵌入 JPEG 二进制流，不会二次压缩导致画质损失
- **HEAD 依赖**：自动探测功能依赖服务器支持 HEAD 请求，若不支持需手动指定结束页
- **文件名处理**：自动过滤非法字符（\/:*?"<>|），同名文件自动追加序号
