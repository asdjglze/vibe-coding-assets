## 输入
- Compose UI 中存在频繁触发的状态流（如阅读进度、列表项状态）
- 当前 UI 存在因状态微小变化导致整页或大组件重组导致的卡顿

## 步骤
1. **去重更新**：在 ViewModel 中记录状态前，先比较新旧值是否相同，若未变化则不更新 StateFlow，避免触发下游重组。
2. **订阅下沉**：将顶层组件不再直接订阅该状态流，改为由内部子组件（如抽屉、侧边栏）单独 `collectAsState` 订阅。
3. **验证效果**：确认状态变化仅重组最小必要区域，整页或其他无关区域不再触发 recomposition。

## 输出
UI 仅在特定子组件内响应状态变化，整页及无关区域保持静止，消除因无效状态更新导致的卡顿。

## 注意事项
- 此策略适用于“状态变化频率高但有效变化少”的场景（如滚动中的进度计算、高频传感器数据）。
- 需确保去重逻辑正确，避免遗漏真实的状态变更。
- 订阅下沉需注意作用域管理，防止内存泄漏。
