## 输入
- 需求：将某类后台自动查询功能（如站点数据富化）从自动流程中撤出，改为供AI按需调用的工具接口，同时保留原有的预调用机制。

## 步骤
1. **确认架构**：分析原功能模块（如 `enrich_site.py`）与底层查询入口（如 `std_sites.lookup_std`），确认其包含的缓存、限速等基础设施。
2. **新增工具函数**：在 Agent 核心文件（如 `agent.py`）中编写新工具函数，直接复用底层查询入口及共享缓存/限速逻辑，确保 AI 调用与原有预调用互不重复爬取。
3. **注册工具**：将新工具加入 `_TOOL_FNS` 字典和 `_ACTION_NAMES` 显示名列表，并在系统提示词（如 `agent_system.md`）的工具清单中登记说明及用法。
4. **移除自动段**：在运行脚本（如 `run.py`）中注释或移除该功能的自动执行代码块，保留模块文件以备后用。
5. **验证**：通过冒烟测试验证工具注册成功、参数校验正确、真实网络调用有效且缓存共享正常。

## 输出
- 原自动流程被移除，不再占用每轮资源。
- 新增 AI 工具可供多轮会话按需调用，返回结构化详情。
- 原有预调用机制保留，两者共享同一套缓存与限速策略。

## 注意事项
- 需区分“单轮 chat 会话”（通常无工具调用能力，依赖预调用）与“多轮 agent 会话”（支持工具调用）的使用场景。
- 工具实现应复用现有基础设施（缓存/限速），避免重复造轮子导致资源浪费。
