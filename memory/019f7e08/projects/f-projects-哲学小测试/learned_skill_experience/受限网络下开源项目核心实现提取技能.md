## 输入
- 目标开源项目的 GitHub 仓库地址
- 需要查找的具体功能模块关键词（如 image, vision）

## 步骤
1. **环境探测**：优先尝试 WebFetch/WebSearch 获取源码或文档。
2. **网络受阻处理**：若直连失败（Connection reset/403/429），使用 Git 加速镜像（如 `ghfast.top`）进行浅克隆。
3. **按需拉取**：使用 `git clone --filter=blob:none --sparse` 仅拉取元数据，随后通过 `git sparse-checkout set <目录>` 按需展开关键源码目录（如 `apps`, `sdk`）。
4. **精准定位**：利用 Grep 工具在本地源码中搜索特定关键词（如 `compressImage`, `formatImagesIntoBlocks`）。
5. **逻辑提取**：阅读匹配文件的关键函数，总结其输入、处理逻辑和输出模式。

## 输出
- 目标功能的实现机制描述（如：图片如何被注入消息上下文）
- 关键配置参数（如：最大边长限制、压缩格式）

## 注意事项
- **Git Sparse Checkout** 是解决大型仓库下载慢/空间不足的核心手段。
- 注意区分“常驻上下文”与“轮次级上下文”，通过源码中的变量传递方式判断。
- 若无 rg (ripgrep)，直接使用内置 Grep 工具即可。
