## 输入
- Python 数据迁移或归档脚本（如 migrate_v2.py）
- 相关的业务逻辑模块（如 standard.py, tagger.py）

## 步骤
1. **配置隔离检查**：检查是否使用 `dict()` 浅拷贝配置对象，若存在嵌套字典（如 permissions），应改用 `copy.deepcopy` 防止修改副本时污染全局配置。
2. **幂等性闭环验证**：对于依赖外部服务（如 AI 刮削编号/文号）生成身份键的场景，必须确保在外部服务调用后重新计算身份键，并增加“第二段已在判定”逻辑（即：若库中已有同键记录，直接跳过或清理临时文件），防止重跑产生重复副本。
3. **异常安全处理**：为所有可能抛出异常的异步或外部调用变量（如 AI 返回结果 `at`）设置默认初始值（如 `None`），并在后续使用时增加类型检查（如 `isinstance(at, dict)`），防止单点失败导致整个批处理中断。
4. **性能与范围优化**：检查收尾阶段的全量操作（如全库打标、富化），将其改为仅针对本批次新增数据的增量操作，避免对已处理数据重复消耗资源。
5. **静态扫描与真实测试**：使用 `pyflakes` 清理未引用代码；使用真实文件名格式（注意 Windows 下全角 `/` 与半角 `/` 的区别）进行解析逻辑测试，排除环境模拟带来的误判。

## 输出
- 修复后的脚本，具备配置隔离、幂等保障、异常容错和高性能收尾能力。
- 通过静态扫描和语法检查。

## 注意事项
- 政策类等无法程序提取编号的文件，需明确标注 `--no-ai` 模式下的幂等风险。
- 真实文件名中的特殊字符（如全角斜杠）可能与测试用例不同，需特别注意。
