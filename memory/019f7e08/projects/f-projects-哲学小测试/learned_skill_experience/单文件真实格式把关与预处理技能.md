## 输入
- 待处理的文件绝对路径
- 是否演练模式（dry_run）

## 步骤
1. **真实格式检测**：使用 `detect_real_type` 读取文件魔数（Magic Number）判断真实类型（如区分 epub 与 zip，pdf 与 txt）。
2. **后缀修正**：若真实类型与当前后缀不符，且属于常用书类/文档格式，则就地重命名为正确后缀（如 `.txt` 伪装 `.pdf` → 改为 `.txt`）。
3. **压缩包处理**：若识别为真压缩包（zip/rar/7z），调用 `unpack_one` 就地解压至「主干_解压」目录，原件移入 `_merged_src` 备份；若为伪压缩包（如 epub/docx）则不解压。
4. **结果路由**：根据 action（renamed/unpacked/unchanged）决定后续流程（改名后继续处理，解压后标记 pending 下轮处理）。

## 输出
- 字典对象：`{"real": "真实类型", "path": "处理后路径", "action": "renamed|unpacked|unchanged|unpack_failed"}`

## 注意事项
- **按需原则**：仅在文件即将被真正处理前调用，禁止全量扫描修复。
- **链式后缀剥离**：书名兜底时需剥净常规层（如 `xxx.rar.zip.pdf` → `xxx`），但解析时以魔数为准。
- **小众忽略**：不识别小众冷门格式，原样放行由 AI 或归档自行判断。
- **扩展资源**：依赖 `src.file_type.detect_real_type` 进行魔数识别。
