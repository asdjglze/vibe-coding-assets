## 输入
- 语料库数据库路径 (如 quote.db)
- 人物名字笔画字典路径 (stroke_dict.json)
- 排序规则定义 (如：马恩列毛斯置顶 + 其余按笔画序 + 人物内按书架序)

## 步骤
1. **生成笔画字典**：运行脚本将数据库中的生僻字映射为笔画数，确保与 App 端逻辑一致。
2. **构建人物排序列表**：
   - 提取有书籍的人物 ID。
   - 优先按固定置顶名单顺序筛选。
   - 其余人物按笔画序列逐字比较，全同则按入库 ID 升序。
3. **全局连续编号**：
   - 遍历排序后的人物，在人物内部按书架规则（类别/年份/卷序）排序书籍。
   - 从 1 开始对每本书重新赋值 sortOrder，保证全局唯一且连续。
4. **幂等验证**：再次运行脚本，确认无改动或仅输出“无需修改”。

## 输出
- 成功：打印修复记录（旧值->新值）及最终顺序预览；重复运行显示“无需修改”。
- 失败：抛出异常（如字典缺失、SQL 绑定错误）并终止打包。

## 注意事项
- **SQL 参数绑定**：使用 `IN (?)` 查询动态列表时，必须显式传入参数元组 `(param_list)`，否则会导致 `ProgrammingError: Incorrect number of bindings supplied`。
- **排序一致性**：打包时的排序逻辑必须与 App 端 UI 展示逻辑完全一致，否则会导致“全部”页排序错乱。
- **数据回写**：校验脚本会直接修改源数据库，需确保在打包流程中后续步骤能同步修复后的数据库文件。
