## 输入
- 发现构建脚本存在功能缺陷或遗漏（如未同步更新版本校验文件）

## 步骤
1. **拒绝临时方案**：禁止编写一次性临时脚本绕过问题，这会导致下次构建重复踩坑。
2. **定位并修改源脚本**：找到对应的构建入口脚本（如 `build_pack.ps1`、`build.bat`）。
3. **固化修复逻辑**：将修复代码直接写入脚本流程中（例如在复制 DB 后自动调用 `Get-FileHash` 重算 MD5 并写入文件）。
4. **清理与验证**：删除任何临时辅助脚本，运行完整构建流程确认修复生效。

## 输出
构建脚本已包含完整的自动化修复逻辑，无需人工干预即可保证数据一致性。

## 注意事项
- 核心原则：所有针对构建流程的修复必须永久固化在脚本中，确保每次构建都自动应用。
- 涉及多平台脚本（如 PowerShell 和 Batch）时，需保持行为一致。
