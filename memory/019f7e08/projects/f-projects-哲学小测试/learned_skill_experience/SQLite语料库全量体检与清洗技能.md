## 输入
- SQLite数据库文件路径
- 需要验证的实体关系（如人物、书籍、文章、目录、语录）

## 步骤
1. **结构探查**：列出所有表名及行数，确认基础数据规模。
2. **全量完整性校验**：编写脚本检查各表字段非空约束、外键关联有效性（孤儿记录）、排序唯一性。
3. **交叉一致性检查**：验证多表间的逻辑对应（如文章归属人物与书籍归属人物是否一致）。
4. **异常数据排查**：针对校验结果中的疑点（如内容过短、引用缺失），深入查询明细并定位根因。
5. **数据清洗与修复**：删除无效垃圾数据（如无正文的导航残留页），修复断裂的关联（如将孤立目录节点指向正确的索引文章）。
6. **最终复核与同步**：再次运行全量校验确保零错误，并将修改同步至目标环境。

## 输出
一份包含各表健康度报告及修复记录的完整校验结果，确保数据库无孤儿记录、无断链、无脏数据。

## 注意事项
- 校验脚本应覆盖所有核心表的 `COUNT(*)` 和 `LEFT JOIN ... IS NULL` 孤儿检测。
- 对于“空书”等边缘情况，需区分是设计如此（如语录集）还是数据抓取遗漏。
- 删除操作前务必确认该数据未被其他表（如语录表）引用。
