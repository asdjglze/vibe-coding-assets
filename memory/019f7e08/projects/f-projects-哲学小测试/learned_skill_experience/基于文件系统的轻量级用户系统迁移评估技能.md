## 输入
- 待迁移项目的本地代码库或备份目录路径

## 步骤
1. 扫描项目目录，寻找现有的迁移文档、部署说明或备份快照（如 `server_backup` 目录）
2. 读取核心配置文件（如 nginx conf、账号表 tsv/json、认证脚本 php/html），识别数据存储形式（数据库 vs 文本文件）
3. 检查是否有现成的迁移清单或手册，提取关键依赖项（如外部服务、特定路径）
4. 分析数据一致性风险（如快照时间戳、动态生成的 token 映射）
5. 综合判断迁移可行性并生成迁移执行清单

## 输出
- 迁移可行性结论（能/不能/需改造）
- 具体的迁移文件清单及目标路径
- 潜在风险提示（如数据时效性、配置缺失）

## 注意事项
- 若存在数据库依赖，需额外考虑 dump/restore 流程
- 注意区分静态备份与运行时状态，避免使用过期快照覆盖新数据
