## 输入
- 待批量更新的数据库表（含唯一ID和名称字段）
- 待写入的数据列表（包含ID、名称、新值）

## 步骤
1. **预检查与备份**：在修改前备份原数据库文件。
2. **处理已知污染**：若发现部分数据已因ID错位被错误写入，先单独定位并修正这些特定行（清空或覆盖为正确值）。
3. **双重校验写入**：
   - 遍历待写入列表，对每条记录执行 `SELECT name FROM table WHERE id=?`。
   - **强制比对**：将查询到的实际名称与列表中预期的名称进行字符串比对。
   - **中止机制**：一旦发现名称不匹配（说明ID索引发生偏移），立即停止脚本并报错，防止错误扩散。
4. **业务逻辑校验**：在写入前增加额外约束检查（如出生年份必须等于 lifespan 中的起始年），拦截明显矛盾数据。
5. **后验证**：扫描所有已更新记录，检查格式合法性及业务约束一致性。

## 输出
- 成功写入的记录数
- 被校验拦截的异常记录数（0为佳）
- 最终状态报告（含备份文件名）

## 注意事项
- **核心风险**：批量更新依赖ID顺序时，极易因列表排序与数据库ID不一致导致“静默污染”（数据写对了位置但属于了别人）。
- **防御策略**：永远不要只信任ID，必须结合名称等语义字段进行二次校验；一旦校验失败应中止而非跳过。
- **扩展资源**：适用于任何基于ID映射的批量数据同步场景。
