## 输入
- manifest.json 文件路径
- 需要重排的模板列表及新名称映射表
- 需要同步修改的 HTML 模板文件

## 步骤
1. **解析 manifest**：读取 JSON，提取每个模板块的 index/name/file/tags
2. **主体分组**：根据 file basename 或 tags 识别同主体模板组（如 Apple/Spotify/NASA）
3. **规划新顺序**：将同主体模板聚拢到连续区间，重新分配 index（从 1 开始连续编号）
4. **生成 PowerShell 脚本**：
   - 使用正则匹配块边界（`{` 和 `}`）
   - 遍历原始顺序，按新顺序重组块
   - 在重组过程中替换 name 字段（注意中文字符编码问题，建议使用 Unicode 码点构造，如 `[string][char]0x5206`）
   - 处理块间分隔符，避免双逗号等 JSON 语法错误
5. **执行脚本并验证**：
   - 运行脚本生成新 manifest
   - 验证 JSON 合法性（ConvertFrom-Json）
   - 检查无重名（Group-Object | Where-Object Count -gt 1）
   - 字节级验证关键名称的码点是否正确
6. **同步修改 HTML 模板**：
   - 根据需求修改特定模板的 CSS/HTML（如 fit-title 逻辑、ab-sub 内容等）
   - 验证磁盘落盘状态（ReadAllBytes + Contains 检查）
7. **清理临时文件**：删除备份文件和脚本

## 输出
- 更新后的 manifest.json（index 重编、名称更新、同主体相邻）
- 修改后的 HTML 模板文件
- 验证通过的预览工具（如有）

## 注意事项
- **中文字符编码**：PowerShell 脚本中直接写中文可能因终端编码导致匹配失败，建议使用 Unicode 码点构造字符串（如 `$yi = [string][char]0x5B9C; $jia = [string][char]0x5BB6`）
- **JSON 格式**：块拼接时注意尾部逗号和分隔符，避免产生双逗号（`,,`）
- **App 端兼容性**：确认 App 端是否依赖 index 进行历史引用，通常 App 端按 file 路径加载模板，index 仅用于排序展示，重排安全
- **验证必要性**：SearchReplace 工具可能存在虚假成功，必须通过 Read 或 ReadAllBytes 验证磁盘真实状态
