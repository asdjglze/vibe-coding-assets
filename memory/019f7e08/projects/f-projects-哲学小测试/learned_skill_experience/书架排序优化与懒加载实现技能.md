## 输入
- 用户对书架排序有特定需求（如按卷次、出版年份）
- 用户提出性能优化需求（如书多时懒加载）
- 当前书架排序逻辑或数据状态不明确

## 步骤
1. **诊断数据与逻辑**：查询数据库实际数据（如 `sortOrder`、`publishYear`），对比预期排序，定位根因（如数据错位、字段缺失）。
2. **修复数据（如需）**：编写临时脚本批量修正错误数据（如修正卷序），同步到开发库和打包源。
3. **调整排序规则**：修改 DAO 层 SQL，将排序键调整为符合业务逻辑的组合（如：先分组、再按年份升序、同年份按卷序）。
4. **实现懒加载**：复用项目中已有的分页模式（如搜索结果列表），在 ViewModel 增加分页状态（`visibleCount`）和加载方法（`loadMore`），在 UI 层根据状态动态渲染并添加 footer 触发器。

## 输出
- 书架按指定规则（如出版年份）正确排序
- 大量数据下界面流畅，无内存爆炸风险
- 编译通过，功能正常

## 注意事项
- 数据修复需同时更新开发库和 assets 中的源库，避免运行时不一致
- 懒加载模式可复用项目中已有的搜索列表分页实现，减少重复代码
