## Goal
源码不可得时，直接对已发布的 Vite 构建产物做小改动并安全上线（防缓存、防模块图损坏）。

## Steps
1. 全量拉取现行产物并哈希核对；只改确需改动的文件。
2. 改动文件一律换新文件名（如 xxx-custom1.js）防强缓存。
3. 同步改写整个模块图的互相引用：index.html 入口 src、入口包内 __vite__mapDeps 数组与动态 import 路径、每个被改名 chunk 的静态 import；确保所有 chunk 引用同一个入口文件名（引用不一致会加载出第二份入口模块）。
4. 语法检查用 node --check（ESM 需临时改 .mjs 后缀）。
5. 本地假数据静态服务 + 无头浏览器整页验证：Edge/Chrome 的 --dump-dom 配合 --virtual-time-budget=N 可让定时器快进，dump 出的 DOM 是多次轮询后的最终状态，适合验证轮询/动画类逻辑；再从产物中抽取新代码配模拟时钟做机制级单测（rAF、定时器、生命周期清理）。
6. 上传顺序：先 assets 后入口 HTML；逐个回读 sha256 比对；旧文件保留可回滚。

## Notes
- 只改文件名不改内部引用 → 加载第二份入口包（Vue 双实例）：onMounted 等生命周期钩子会静默失效、并有多实例告警，页面部分渲染正常但数据不更新，隐蔽性强。
- 浏览器报 "Failed to fetch dynamically imported module" 时优先排查 404 引用（重命名漏改/文件缺失），而非先怀疑语法错误。
