## 输入
- 用户反馈的具体 Bug 现象（如：分享页数据丢失、定位与选中不一致、搜索高亮样式不符预期）
- 相关代码文件路径或组件名称（可选，用于快速定位）

## 步骤
1. **定位根因**：
   - 对于数据传递问题：检查 Kotlin 侧 `@JavascriptInterface` 方法是否存在同名属性 getter 冲突（如 `getData()` 同时作为属性和桥方法），使用 `javap` 反编译确认方法签名；检查 JS 侧获取数据的逻辑是否依赖可能失效的桥方法。
   - 对于定位与选中不一致：对比定位逻辑（如 `findJumpBlockIndex` 使用的 `doc.blocks` 空间）与选区逻辑（`getSelectableTexts` 使用的可视文本空间）是否同源，若不同源需统一匹配策略或映射关系。
   - 对于样式问题：检查渲染层是否传递了过时的状态参数（如 `highlightBlockIndex`），确认是否需要移除整块背景改为片段高亮。
2. **实施修复**：
   - 数据传递：重命名属性消除方法冲突，或在页面加载完成后主动调用 `evaluateJavascript` 推送 JSON 兜底。
   - 定位修正：重构选区函数返回匹配结果（块文本 + 比例），在滚动前将匹配块映射回文档空间计算精确位置。
   - 样式调整：移除整块背景参数，改用命中角色（当前项/其余项）控制片段高亮的深浅色。
3. **验证**：编译通过 → 重新打包 → 测试用户反馈场景。

## 输出
修复后的 APK 及对应的代码变更说明。

## 注意事项
- Android Compose 中 `SelectionContainer` 的字符序列可能与底层解析树不一致，需确保定位与选区使用同一套文本空间或建立可靠映射。
- `@JavascriptInterface` 方法若与属性 getter 同名，JS 侧可能无法正确调用，需通过反编译确认实际暴露的方法。
- 搜索高亮若需区分「当前项」与「其余项」，应通过命中角色（role）控制配色，而非依赖临时高亮块状态。
