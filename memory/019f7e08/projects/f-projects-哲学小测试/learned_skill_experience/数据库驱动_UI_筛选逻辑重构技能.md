## 输入
- 业务规则变更需求（如：某列表项的筛选条件需基于数据库多表联合判定）

## 步骤
1. 分析现有数据模型：确认涉及的数据表及关联关系（如 book, quote, article 表）
2. 编写 SQL 查询：使用 UNION 合并多个表的记录 ID，构建新的筛选逻辑（如 `SELECT personId FROM book UNION SELECT personId FROM quote ...`）
3. 更新 DAO 层：在 Dao 接口添加新查询方法，实现上述 SQL 逻辑
4. 更新 Repository 层：调用新 DAO 方法获取 ID 集合，过滤实体列表，返回符合新规则的子集
5. 更新 ViewModel/UI 层：将原本调用的旧方法替换为新方法，确保 UI 数据源一致
6. 全局搜索验证：Grep 检查是否有其他入口遗漏修改，确保职责分离（如人物选择仍用宽松规则，书架用严格规则）
7. 编译与打包验证：运行 Gradle 编译并打包，确认无代码错误且资源正确同步

## 输出
- 代码编译通过（BUILD SUCCESSFUL）
- 打包产物中数据逻辑生效（如 APK 内数据库列增加、筛选结果符合预期）

## 注意事项
- 避免硬编码映射：所有筛选逻辑应完全由数据库查询驱动，数据变动时规则自动生效
- 区分不同场景的判定粒度：同一数据在不同 UI 场景（如书架 vs 人物选择）可能适用不同筛选标准，需分别实现
