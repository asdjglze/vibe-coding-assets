## 输入
- Ollama Agent 代码实现
- 明确的业务约束：准确率第一，禁止编造分类号，AI负责信息检索与实质判断

## 步骤
1. **动作协议双读**：解决提示词示例（顶层code）与代码解析（args嵌套）不一致导致的空参失败，代码需兼容两种格式。
2. **上下文滑动窗口**：防止history全量堆积导致token溢出和头部截断（失忆），对超长工具结果自动压缩，保留关键事实。
3. **元数据状态回填**：程序维护已确认元数据清单（书名/作者等），每轮重发给AI，防止后续生成时遗忘。
4. **线索与先验分离**：目录名仅作为检索线索，不作为直通分类依据（如《禅与摩托车维修艺术》不能因目录名归入机械类）。
5. **程序化上下文管理**：Ollama是无状态API，无自带记忆。由程序控制拼接：token预算超限先压缩再发，永不触服务端截断；最近N轮完整+旧轮折叠进事实清单；压缩用独立LLM调用，不占agent轮数。
6. **错误重试分层**：网络失败→程序降级关闭联网工具不重试；工具问题→工具层重试；AI判断问题→AI重试。
7. **固定流水线决策**：放弃自由探索型Agent，改为固定流水线+选择题。答案空间确定时，不需要模型进行规划或试错。
8. **视觉单次化**：仅在需要读取图像信息时调用一次视觉模型，后续步骤仅依赖文本证据。
9. **人工兜底**：遇到无法自动解决的歧义，直接转人工，不要试图通过增加轮数来解决。

## 输出
- 准确的图书分类路径及置信度
- 稳定的Agent运行状态（无协议报错、无上下文丢失）

## 注意事项
- 分类号必须从官方候选中选择，零编造。
- 跨学科或体裁歧义书（如哲学小说）应标记低置信度留人工，而非强行归类。
- 速度不是优化目标，正确率为唯一指标。
- 网页抓取超时建议30~60s（慢网站也等）。
