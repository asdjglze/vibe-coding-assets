## 输入
- 用户关于首次启动页交互的具体需求（如：首次必须点击按钮确认，后续自动进入）
- 需要展示的详细文案内容或核心理念

## 步骤
1. **创建持久化存储**：新建 `Store` 类（参考项目现有 `ReaderSettingsStore` 等写法），使用 `SharedPreferences` 保存同意标记（如 `KEY_ACCEPTED`），提供 `isAccepted()` 和 `markAccepted()` 方法。
2. **注册全局单例**：在 `Application` 类中懒加载并注册该 Store 实例，确保全应用共享状态。
3. **修改启动逻辑**：在 `MainActivity` 中读取 Store 状态，区分“首次进入”和“已同意”两种分支：
   - 首次：UI 显示确认按钮，点击后调用 `markAccepted()` 并跳转。
   - 已同意：直接显示加载页，按原有时长自动跳转。
4. **重构 UI 组件**：更新启动页 Composable，支持传入 `accepted` 参数动态切换底部内容（按钮 vs 加载提示），并将正文区改为可滚动布局以容纳长文案。
5. **文案植入**：将用户提供的核心理念（如版本对比、历史背景、独立思考等）分段写入文本组件，保持字体和配色风格一致。

## 输出
- 编译通过的应用，首次安装时强制弹出带按钮的免责声明页，后续启动自动跳过按钮环节。
- 免责声明页包含完整的扩展文案，布局适配不同屏幕高度（标题固定、正文滚动）。

## 注意事项
- 持久化键名需与项目其他 Store 保持一致的命名规范（如 `KEY_XXX`）。
- 按钮交互需确保点击后立即落盘并跳转，避免用户重复点击或状态不同步。
- 长文案务必使用 `verticalScroll` 防止溢出，同时保持阅读体验流畅。
