## 输入
- 应用页面加载或渲染明显卡顿（如等待数秒）
- 涉及 Markdown/文本内容解析的场景

## 步骤
1. **搜索解析调用**：使用 Grep 搜索解析器入口（如 `MdParser.parse`、`CommonMark` 等），统计同一数据源的调用次数。
2. **定位冗余点**：检查 UI 层（如 Compose `remember` 块）、ViewModel 逻辑中是否存在多处独立解析同一内容的情况。
3. **提取共享结果**：在数据源入口处（如 ViewModel）解析一次，将解析后的结构化对象（如 `MdDoc`）存入状态。
4. **统一消费**：UI 层各组件直接读取共享的解析结果，移除各自的本地解析逻辑。

## 输出
同一数据源仅解析一次，显著降低 CPU 开销和首屏等待时间。

## 注意事项
- 确保解析后的数据结构足够轻量且线程安全，以便在不同作用域共享。
- 若解析耗时极长，需考虑后台异步解析与 UI 占位符配合。
- 避免为微小的性能优化引入架构复杂性，除非有明确的瓶颈证据。
