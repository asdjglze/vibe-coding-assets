## 输入
- 目标前端项目仅有服务器上的已发布产物（如 /www/wwwroot/opds-web），无本地源码或源码已过时
- 需要修改特定功能（如栏目排序、计数器逻辑）
- 服务器存在强缓存策略（如 /assets/* 30天缓存）

## 步骤
1. **拉取产物**：从服务器下载需修改的完整产物目录（含 index.html 及所有 assets/*.js/css）
2. **打补丁**：在拉取的产物上直接修改业务逻辑（如 JS 字符串替换、函数注入）
3. **统一改名链**：为防缓存和避免 Vue 双实例，必须将所有互相引用的文件统一重命名（如 index-DpIXzSoL -> index-custom1, HomeView-DkcThokB -> HomeView-custom1）
4. **全量引用修复**：遍历所有产物文件（包括入口包、组件包、HTML），将旧文件名替换为新文件名，确保模块图中无任何残留旧引用
5. **验证机制**：
   - 语法检查：node --check 各 JS 文件
   - 探针页测试：创建独立 HTML 加载新模块，确认无双实例、API 正常
   - 无头浏览器渲染：dump-dom 或截图验证 DOM 结构符合预期
6. **上传部署**：先备份原 index.html，逐个上传新文件并 sha256 双向校验，保留旧文件以便回滚

## 输出
- 服务器上运行正常的改版前端（新文件名产物 + 备份的旧文件）
- 本地留存的补丁产物目录（patched_*/）和改前快照（server_snapshot_*/）

## 注意事项
- **核心风险**：仅修改单个文件而忽略其他文件的引用会导致 Vue 双实例（生命周期钩子失效），必须全量扫描并替换所有引用点
- **缓存策略**：若服务器有强缓存，必须通过文件名变更强制刷新；不要尝试覆盖同名文件
- **回滚保障**：上传前务必备份 index.html 和旧版资产文件
