## 任务描述
排查 SQLite 数据库 (quote.db, 231MB) 在 F 盘读取 COUNT 查询时卡死的问题。

## 执行过程
```mermaid
graph TD
    A[现象: F盘 quote.db COUNT 查询超时] --> B[假设1: 进程占用/锁]
    B --> C[执行 _diag_wait.py 长时间等待测试]
    C --> D[结果: 依然卡死, 排除简单超时]
    D --> E[假设2: 磁盘IO故障/杀软扫描]
    E --> F[执行 _diag_temp.py 拷至TEMP盘 & _diag_io.py IO测速]
    F --> G[结果: TEMP盘拷贝也卡, 但顺序读速度正常(1866MB/s)]
    G --> H[假设3: 文件损坏/锁]
    H --> I[执行 Rename 重命名文件测试]
    I --> J[结果: 重命名后依然卡, 排除文件占用]
    J --> K[假设4: 存储介质差异/缓存]
    K --> L[将文件拷至C盘 SSD 执行测试]
    L --> M[结果: C盘副本 0.03s 完成, CHM残留数据正确]
    M --> N[结论: F盘为HDD冷缓存导致随机读极慢, 非文件损坏]
```

## 任务总结
确认 F 盘上的 231MB SQLite 数据库因机械硬盘冷缓存效应，首次随机读取极慢（>60s），而 C 盘 SSD 副本秒级响应。面包屑清理数据完好。建议避免在 HDD 冷启动下直接对大库执行全表扫描，或预热缓存。
