## 任务描述
解决分享卡片页面空白及数据传递失败问题，并实现数据落盘与Debug功能。

## 执行过程
```mermaid
graph TD
    A[需求:修复分享页空白/数据丢失] --> B[定位根因: assets压缩导致openFd失败]
    B --> C[方案1: 资源解压到工作域 files/share_templates/]
    C --> D[实现 ShareTemplateExtractor 后台解压]
    D --> E[修改拦截器优先读取工作域文件]
    E --> F[方案2: 数据落盘与内联注入]
    F --> G[创建 ShareCardStore 处理 JSON 序列化/反序列化]
    G --> H[ReaderScreen 点击分享时写入文件]
    H --> I[ShareCardScreen 优先从文件读取数据]
    I --> J[ShareCardWebView 将 JSON 内联注入 HTML]
    J --> K[share_core.js 优先读取 window.__MAOYULU_DATA__]
    K --> L[添加 Debug 弹窗显示三段 JSON 供核对]
    L --> M[重构 DailyRepository 统一每日人物]
```

## 任务总结
成功修复分享页问题：
1. **资源加载**：实现 `ShareTemplateExtractor` 将模板资源解压至应用私有目录，避免 APK 压缩导致的 `openFd` 失败；拦截器改为优先读取工作域文件。
2. **数据传递**：采用「落盘+内联」双重保障。阅读页点击分享时将数据写入 JSON 文件；分享页启动时优先从文件读取，并通过 `injectPayload` 将 JSON 直接注入 HTML 末尾 (`window.__MAOYULU_DATA__`)，彻底绕过 JS Bridge。
3. **Debug支持**：在切换模板时弹出 Dialog，展示「落盘原文」、「反序列化对象」、「注入模板数据」三段 JSON，便于排查数据不一致问题。
4. **业务逻辑**：重构 `DailyRepository`，确保语录、诗词、文章均基于同一位「今日人物」选取。
