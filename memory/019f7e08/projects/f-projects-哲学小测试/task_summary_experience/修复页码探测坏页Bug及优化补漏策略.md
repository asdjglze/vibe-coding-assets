## 任务描述
排查并恢复因终端窗口回收而终止的大规模电子书下载进程，修复页码探测算法缺陷并优化补漏性能。

## 执行过程
```mermaid
graph TD
    A[用户询问进度] --> B[检查进程状态发现已终止]
    B --> C[分析日志定位断点]
    C --> D[复现问题: 同一本书页码探测结果不一致]
    D --> E[深入分析: 发现服务器存在漂移的'坏页'(HTTP 200非图片)]
    E --> F[定位根因: 二分数组单调性假设被破坏]
    F --> G[修复probe_pages: 增加坏页容忍延伸段]
    G --> H[优化补漏: 减少重试次数和间隔]
    H --> I[使用分离进程方式重启任务]
```

## 任务总结
1. **进程管理**: 发现依赖终端窗口的进程易被系统回收，改用 `Start-Process -WindowStyle Hidden` 分离进程确保稳定性。
2. **算法修复**: 解决了 `probe_pages` 在遇到 HTTP 200 但内容为 HTML 的坏页时，二分查找误判边界的问题。新逻辑在二分后增加逐页延伸，容忍连续坏页。
3. **性能优化**: 将补漏阶段的重试策略从 `tries=3, gap=5s` 调整为 `tries=2, gap=2s`，显著提升了大书缺页补漏的速度。
