## 任务描述
设计图书管理系统的"按需判定"流程与"待人工"流转机制，解决百万级数据下 AI 调用成本过高及自动处理卡点问题。

## 执行过程
```mermaid
graph TD
    A[需求:优化精修阶段流程] --> B[定义"按需判定"核心原则]
    B --> C[确立程序查库优先策略：不每本问AI]
    C --> D[设计三项比对逻辑：标签/字段值/缺失记录库]
    D --> E[细化细分类启动条件：字段空或有待标]
    E --> F[设计缺失记录库：区分"未做"与"不存在"]
    F --> G[定义待人工区锁死语义：一票否决自动重试]
    G --> H[整合富化与校对为同一遍工序]
    H --> I[更新规划文档v1.2落实所有逻辑]
```

## 任务总结
成功构建高效处理流程：1. **按需判定**：程序通过查库（标签+字段+缺失库）毫秒级决定是否启动AI，避免全量调用；2. **缺失记录库**：专用数据库记录"确认不存在"的元数据，防止重复搜索；3. **待人工机制**：卡住的书移入独立分区并挂细分标签，自动流程直接跳过，人工处理后重新参与；4. **富化校对合并**：同一遍AI工序完成，按标签调整侧重但不互斥。
