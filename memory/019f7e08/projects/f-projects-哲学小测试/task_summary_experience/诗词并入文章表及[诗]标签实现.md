## 任务描述
将诗词（poem）并入文章（article）表进行统一存储，同时在App端引入 [诗] 居中标签实现Markdown格式渲染，保持用户感知分离。

## 执行过程
```mermaid
graph TD
    A[需求:诗词并入文章表+新增[诗]标签] --> B[设计: kind/dynasty列 + [诗]块语法]
    B --> C[修改App Entity/Dao: Poem.kt去@Entity, Article.kt加kind/dynasty]
    C --> D[更新App Dao: poemDao改查article WHERE kind='poem']
    D --> E[实现MdParser: 新增Poetic块解析逻辑]
    E --> F[实现MdBody: 新增MdPoeticBody居中逐句渲染器]
    F --> G[改造ReaderScreen/HomeScreen: 诗词走md渲染/剥除[诗]前缀]
    G --> H[编写迁移脚本: ALTER TABLE + 逐行迁入 + 重映射toc_entry]
    H --> I[执行迁移并校验: 备份->迁移->验证一致性]
    I --> J[同步assets库并重算md5]
```

## 任务总结
成功完成诗词并入文章表的存储层重构：
1. **数据层**：Article表增加 `kind` ('article'/'poem') 和 `dynasty` 字段；Poem类转为普通Data Class，由PoemDao投影查询；Room版本升级至v6。
2. **解析与渲染**：新增 `[诗]` 块级标签，支持惰性延续与去前缀；实现 `MdPoeticBody` 居中逐句渲染器，兼容加粗/脚注等行内语法。
3. **迁移与同步**：编写一次性Python脚本完成187首诗词的数据迁移与目录重映射，双副本（notes_editor主库/assets）一致，MD5校验通过。
4. **兼容性**：首页卡片/桌面组件自动剥离 `[诗]` 标记，阅读页诗词走MD渲染，旧数据兜底处理。
