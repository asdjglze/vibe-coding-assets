## 任务描述
修复 Markdown 解析器中块标记（如 [诗]/[题]/[抬]/[款]）与转义符（\ 或 /）的优先级冲突，确保转义行优先被识别为普通文本，不被吸收到格式块中。

## 执行过程
```mermaid
graph TD
    A[需求:转义符优先级高于块标记] --> B[定义转义正则 ESCAPE_HEAD_RE]
    B --> C[App 解析器 Md.kt 主循环最前检查转义行]
    C --> D[校对工具 index.html 主循环最前检查转义行]
    D --> E[修改 [题]/[诗] 惰性延续打断条件加入转义行检测]
    E --> F[修改脚注定义延续打断条件加入转义行检测]
    F --> G[修正纯文本渲染点 WidgetCardRenderer/splitPoeticLines]
    G --> H[剥离转义符后显示字面文本并防止误剥]
    H --> I[编写 Node.js 单测验证正则与逻辑]
    I --> J[浏览器端到端实测验证渲染效果]
```

## 任务总结
成功实现转义符优先级机制：在 App 端 (Md.kt) 和校对工具 (index.html) 中新增 ESCAPE_HEAD_RE 正则，在主扫描循环最前拦截行首 \[标记] 或 /[标记]，剥离转义符后作为普通正文处理；同时更新 [题]/[诗] 及脚注定义的惰性延续打断逻辑，确保转义行能正确打断块结构；修正桌面组件与诗词兜底的纯文本化逻辑，避免误剥字面标记。经 Node 单测与浏览器实测验证，转义行显示为字面文本且不干扰正常格式块渲染。
