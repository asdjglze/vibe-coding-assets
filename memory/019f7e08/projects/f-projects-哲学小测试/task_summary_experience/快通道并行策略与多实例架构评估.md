## 任务描述
评估‘快速通道’（批量文件整理发布）采用并行处理的可行性与最佳方案。

## 执行过程
```mermaid
graph TD
    A[需求:评估快通道并行效率] --> B[搜索快通道核心代码 quick_publish.py]
    B --> C[检查并发安全机制 instance_lock.py run.py]
    C --> D[分析瓶颈:快通道为纯 IO 活 (解压/挪文件/NAS 读写)]
    D --> E[确认现有架构:已支持 --instance N 多实例协同]
    E --> F[提出三方案:多开实例/快通道∥精修/单实例线程池]
    F --> G[识别隐患:同名文件毫秒级竞态]
    G --> H[输出建议:首选快通道与精修双实例并行]
```

## 任务总结
确认快通道采用并行处理收益显著（重叠 IO 等待时间）。现有架构已完美支持多实例（文件认领锁 + 发布单写锁），无需修改代码即可实现：
1. **方案 A**：多开快通道实例（如 --instance 1, 2）自动分流文件；
2. **方案 B（推荐）**：一个实例跑快通道，另一个跑 AI 精修链，两者时间互补，整体吞吐最优；
3. **方案 C**：不推荐单实例内部改线程池（重复建设）。
同时指出同名文件在极端并发下存在微小竞态风险，建议后续加固原子占位逻辑。
