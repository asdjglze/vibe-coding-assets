图书分类系统架构决策（用户明确确认）：1. 目标是 AI 准确高效工作，不是单纯求快——关键词匹配也快但无意义。2. Agent 的探索/试错能力不用于编造分类号（分类号必须从官方表候选选择+程序校验，零编造），AI 能力用在信息检索与判断上；元数据不搞轮数状态机——AI 信息不够就调工具取，够了直接 final 一口气输出。3. 放弃外部书目库自动刮削主路径。4. 协议修复三重保险：提示词严格约束（只输出一个 JSON 对象、禁止额外内容）→ 统一单一格式（一律 args 嵌套）→ 代码双读兜底。5. Ollama 是无状态 API 无自带记忆，上下文必须由程序自己拼接：token 预算（估算超限先压缩再发，永不触服务端截断）+ 分层窗口（最近 N 轮完整+旧轮折叠进事实清单）+ 超长工具结果自动压缩；压缩用独立 LLM 调用，不占 agent 轮数。6. 错误重试分层：网络失败→程序降级关闭联网工具不重试；工具问题→工具层重试；AI 判断问题→AI 重试。7. 目录名只是存放者粗分类线索，书名是作者起的名字不是分类，一律按内容实质与体裁归类（《禅与摩托车维修艺术》→I712.45 文学）。8. 网页抓取超时 30~60s（慢网站也等）。9. 评测以分类正确率为唯一目标，不预设成功率数字。
